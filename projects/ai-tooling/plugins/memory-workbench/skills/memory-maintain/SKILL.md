# 维护记忆

先判断记录属于当前项目还是跨项目。项目特有的根因、路径、复现方式和验证范围写入项目仓库根目录的 `docs/codex-memory.md`。只有用户要求沉淀为全局经验时，才把可跨项目复用的规则写入 Codex 主目录下的 `memory-workbench/global.md`。主目录使用有效的 `CODEX_HOME`，未设置时为用户主目录下的 `.codex`。全局台账保持本地，项目台账可随代码用 Git 审阅。已有仓库台账、授权和项目指令优先适用。

## 更新条目

1. 用当前任务所属的 Git 根目录确定项目；非 Git 项目使用用户明确指定的根目录。在写入前阅读适用的项目指令和现有台账。用症状、错误和模块搜索同类条目并就地更新，保留稳定 ID。修复尚未验证时，把假设和后续验证动作写清楚。
2. 采用 [台账格式](references/ledger.md)。记录这条经验会改变的下一次动作，以及支撑它的代码、提交、日志或测试结果。保存前检查内容是否适合目标范围，移除密钥和无关敏感信息。用户要求整理历史时，先筛选并逐条核对候选项；自动生成的摘要只能作为线索。
3. 有更可靠结论时，更新原条目；存在需要保留的历史分歧时，标为「已替代」并写出新条目 ID。合并时把有效证据归到保留的条目并留下指向。写入前读取最新文件，若目标条目已被并发更改，重新核对后再合并。最后报告范围、条目 ID、变更和验证状态。
4. 这些台账独立于 Codex 的自动记忆。现有自动记忆文件保持只读；如果用户明确要求 Codex 自身记住或忘记某条信息，则遵循运行环境提供的记忆写入或删除流程。插件自身的全局台账写入仍受宿主文件权限约束，受限时交付可审阅的条目草案并说明保存位置。

## 接入既有工作流

用户要求为仓库接入时，检查现有 `AGENTS.md`，以最小改动加入下面的触发规则并保留其他内容。安装插件本身不触发仓库编辑；没有使用插件时，规则也可以直接通过读取台账执行。

> 修复重复出现的故障前，查阅 `docs/codex-memory.md` 中对应模块；可用时调用记忆工作台的 `memory-search`。本次修复经过验证且有可复用的结论时，在交付前使用 `memory-maintain` 新增或更新一条项目记录，附验证范围和来源。日常实现沿用现有项目约定。

用户也可以在现有发布、复盘或评审 Skill 中引用同一触发规则。每次都要执行的短规则放进相应范围的 `AGENTS.md`，完整证据留在台账里。全局晋升按用户指定执行。
