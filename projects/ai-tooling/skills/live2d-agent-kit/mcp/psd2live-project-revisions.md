# PSD2Live 工程修订、采样与冻结备份

用于现有工程的受控修改，补充 [MCP 总览](README.md)。
这些是后续 Windows 项目的实测经验，不是对所有 PSD2Live 版本的固定 API 契约。

## 连接与工程身份

优先使用当前宿主已连接的工具。工具不足时，可使用用户授权的本机接口或 CLI。
“服务可访问”不是“已找到正确工程”：先读取实际 project ID、state、图层与参数信息，
核对工程文件、代表性图层和中性预览。
有些 overview 的 layers/parameters/physics/motions 是含 total/items 的对象，不是直接数组。

使用用户提供或当前应用显示的地址与鉴权。不要把 token、Authorization 头或具体用户配置
写入技能、通用脚本、日志、截图、源工程说明或公开仓库。
直接 JSON-RPC 回退只在必要时使用，不等于已经把 MCP 注册为宿主内置工具。

重新发现服务的工具和操作 schema。工具包总 schema 不一定说明每个 operation 接收的字段：
某次实现的 sample_motion 接收工程状态和请求 ID，而 render_model 仅接收 viewport、
parameters、background 等字段。不可把同一个 request 模板盲目套给所有操作。

## 先备份，再导入，顺序修改

1. 核对当前活动工程身份。需要切换时先保留其未保存修改。
2. 保存到独立修订目录，再读取最新状态；不要为绕过 unsaved_changes 直接 discard。
3. 导入明确的 CMO/工程文件，检查返回结果确已完成，再重新读 overview。
4. 按实际图层名与 ID 安装对应素材。需要保留绑定时，使用本版本支持的等效选项，
   保留逻辑位置和网格；例如经验证的 layer_replace_image + fit=stretch + rebuild_mesh=false。
   该选项保留拓扑，不能修复源素材错误或自动保证注册一致。
5. 每次状态变更后取新 state；保存最终工程，并复查当前活动工程就是交付版本。

操作超时先查结果与状态，不能盲目重复创建图层或动作。
异步调用返回任务标识时按该服务的任务接口等待完成。
复制运行包、写源码和执行导入有依赖顺序，不能为了并行打乱。

## 纹理、工程与运行包分别验证

有些 CMO 导入路径会从图集重建编辑图层，不能承诺还保留原 PSD 编辑链。
记录 source PSD、逻辑注册图、高清编辑图和运行图集各自的实际分辨率。

几何/UV 生成后才能注入对应高清图集，保留原布局与源哈希关系。
编辑器替换高清 PNG 不代表旧导出的 runtime 也已更新；运行包重新构建后也不代表 GUI 已加载它。
按最终文件和当前工程分别核对，避免看新图、播放旧模型。

动作导入后检查曲线、参数 ID 和时长，不仅核对 motion 数量。
采样读取返回的 physicsSimulated、backend、sampleTimes、fps 和 tile/imageRect，
而不是从工具名字推断“原生渲染”。按真实采样时刻拼接 GIF，防止重复帧或时间轴变形。
图像 content 是媒体数据，不要把 base64 全量打印进日志。

## 冻结备份与可重建交付

用户要求“备份这一版”时，冻结其指定版本，不以最新修改时间代替版本身份。
保存到新目录，逐文件比较源与副本 SHA-256，清单记录相对路径、字节数、哈希、
带时区的时间、基准版本和明确排除项。不要把 rejected/before 工程混称为同一最终产物。

备份通常包含：
- 当前编辑工程、CMO、MOC、model3、纹理、物理、动作与表情依赖。
- 分层源文件、完整部件素材、注册说明。
- 该版本的预览、验证范围、已知问题与用户验收状态。
- 要求“可重建”时，另收 manifest、配方/补丁、所需基准输入、工具版本与构建入口。

能够打开/运行、复制哈希一致、能够从源码重建，是三个不同结论。
只有运行模型和 PSD 的备份不能宣称已包含全部生成配方。
冻结备份后产生的新修正应另建修订；没有明确请求时不改旧备份，不扩大到发布或上传。

完成说明应给出当前工程入口、恢复方法、实际完成的检查和仍需用户实机确认的部分。
