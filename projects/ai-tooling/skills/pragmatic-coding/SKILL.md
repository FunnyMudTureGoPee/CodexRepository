# 务实编码

围绕用户可观察的结果完成工作。选择足以正确解决当前问题、维护成本较低的实现；精简不能成为漏做需求、掩盖错误或跳过必要验证的理由。

## 控制改动范围

先从任务、适用的仓库说明和直接相关代码确定：要改变什么行为，哪些调用者和状态会受影响，什么证据足以结束。简单修改在内部完成判断即可，不必额外生成计划、清单或设计文档。

- 优先沿用现有实现、依赖和错误处理方式。先检查直接调用链和相关测试，有具体疑点再扩大搜索。
- 只修复完成任务所需的问题。不要顺手清理无关命名、格式、依赖、架构或历史缺陷。
- 不为假想的未来需求新增配置开关、兼容分支、插件接口或通用框架。有明确复用、边界隔离或复杂度收益时才抽象；不按调用次数机械决定。
- 变更范围按行为完整性决定，不追求最少行数。修复根因以及必要调用者，避免靠局部特判维持错误状态。

## 在真实边界防御

新增检查前，能指出它保护的边界或不变量，以及实际可能发生的失败。依据来自输入来源、类型契约、调用链、生命周期、外部系统语义或已有缺陷；不要求先发生事故才保护可信的风险。

- 对用户输入、网络响应、文件、配置等外部数据，在进入可信内部模型时校验；对权限、路径安全和不可逆写入保留必要保护。
- 内部契约已经保证的条件，不要在每一层重复检查。可变化的状态、跨异步边界和生命周期变化仍需在使用处按实际语义检查。
- 区分合法缺省与程序错误。必需依赖缺失、非法状态或失败结果，不要用空对象、空集合、默认成功值或无声返回掩盖；沿现有契约传播错误。
- 只在能够恢复、补充有用上下文或转换为约定错误的地方捕获异常。资源释放按需使用 finally、using 等机制；不要层层 catch、重复记录同一错误。
- 降级必须具有明确业务语义并让调用者知道结果。重试应针对可恢复失败，有边界且考虑幂等性；沿用平台已有策略，避免叠加重试层或无限重试。
- 不因“减少防御”批量删除既有检查。确认条件确实冗余或妨碍目标后，再在本次范围内精简。

## 验证与风险相称

每个验证动作都应回答一个具体问题：改动是否能被解析或编译、目标行为是否正确、受影响的不变量是否仍成立。先选能发现本次故障的最低成本有效检查，再根据未解决的风险扩展。

| 改动类型 | 合理的起点 |
| --- | --- |
| 文案、注释、低影响配置或样式 | 检查 diff，按需做解析或定点预览；一般不新增自动化测试 |
| 局部逻辑或已知缺陷 | 运行直接相关的现有测试；存在有价值的覆盖缺口时补最小行为回归用例 |
| 接口、序列化、持久化、并发或跨模块行为 | 验证受影响边界及关键失败路径；按实际需要做编译或集成检查 |
| 构建基础设施、广泛共享逻辑或正式发布 | 根据影响范围执行更广验证以及项目明确要求的检查 |

这是选择起点的指导，不是固定测试数量或最高限额。用户明确要求和适用的项目门禁仍需完成。

- 分开决定“是否新增测试”和“运行哪些测试”。能用已有测试证明的行为，不再建立重复用例。
- 测试可观察行为和重要不变量；避免断言实现细节、源码字符串、调用步骤或把实现复制进测试。格式本身是契约时可直接检查格式。
- 缺陷回归优先覆盖能区分修复前后的场景；不要为凑覆盖率穷举无关输入、测试第三方库本身，或为微小改动搭建新测试框架。
- 检查通过后，仅在相关代码或环境发生变化、出现新故障证据、或仍有明确风险时重跑或扩展。不轮换工具反复证明同一结论。
- 检查失败时先区分改动缺陷、已有失败和环境阻塞。只有修复了原因、调整了有效参数或有短暂故障依据时才重试；相同阻塞没有新信息就停止该验证路径。
- 环境不可用时，完成仍可执行的检查，报告具体未验证项及影响。不要为追求绿色结果擅自安装大型工具链、修复无关环境、放宽断言或禁用测试。
- 编译通过只证明编译；静态检查不代表运行时成功。不要把旧日志或其他实例的结果当作本次证据。

## 收尾与停止

交付前检查本次 diff：每个新增分支、抽象、回退与测试是否对应当前需求或具体风险。删除本次引入且没有作用的部分，保留完成目标所需的代码。

目标行为已实现、适用的必需检查已完成、风险相称的证据足够且无新问题时，结束工作。不要自动追加全仓审计、压力测试、全量构建或“再确认一次”。

若必需验证被阻塞，明确报告实现状态与验收缺口，不宣称全部完成。回复简要说明改了什么、用什么验证、哪些重要内容尚未验证；低风险修改无需附带通用风险清单。

## 判断示例

- 调整按钮文字：核对显示位置和 diff；不因此运行整套端到端测试或增加文案匹配测试。
- 修复外部 JSON 的缺失字段：在解析边界处理契约允许的缺省或明确报错；不在所有内部消费者重复判空。
- 修复重复扣款：幂等性和失败后的状态一致性属于核心行为，值得定点回归及必要集成验证；不能以“避免过度防御”为由省略。
- 修复异步回调访问已销毁对象：生命周期变化提供了检查依据；不把这一局部需要推广为所有对象访问都判空。
