# 手动预览任务上下文

在邮件管理页的“任务”页签，点击已保存任务旁的“预览上下文”。选择窗口、最多可读消息数，再点击“获取上下文预览”。

可选择：

- 最近若干小时，默认 6 小时。
- 自上次成功模型判断：读取同任务、同会话的最后一次成功模型判断所用上下文快照之后的消息。模型明确判断不发送也属于成功判断；失败和未调用模型的无新消息跳过不推进此边界。手动试判断也计入成功模型判断。
- 自上次发信的上下文边界：使用最后一次 accepted / partial 发信对应的上下文快照时间。SMTP 传输期间新增消息留在下个窗口。partial 表示至少部分收件人被接受，不表示所有收件人最终收到了邮件。
- 自定义时间段：使用本机时区日历和时间控件，开始时间不含、结束时间包含。结束不能晚于当前时间。

先按时间筛选活动分支，再从新到旧读取，直至达到最多可读消息数。纯图片和其他无正文消息不占该数量；不解码窗口以外的大消息。消息过大时尽力保留分布式文字摘录，继续施加单条、累计解压和最终字符预算保护。达到保护上限时可能产生读取警告或明确错误，不能保证恢复所有原文。

预览是历史正文视图：不包含主插件预设、任务提示词、存储摘要、实时工具结果和图片识别，不代表最终完整模型请求或实际 token 数。字符预算沿用插件上限，并在工具模式预留工具空间；实际模型判断还需容纳提示词等数据，可能进一步裁剪。预览不受任务的新消息数量门槛和新鲜度门槛阻止，以便排查数据。任务中的“最新消息新鲜度”只检查消息是否过旧，不是时间过滤。

预览会显示请求时间、实际保留消息、未读取候选数、压缩记录和缺口提示。主插件已经清理或以摘要替换的原始消息无法凭空恢复；缺少有效时间的消息会计数并排除。找不到对应成功事件时，以当前可用历史作为首次预览，并显示提示。旧记录没有上下文快照时间时使用旧边界估算并提示可能重叠或遗漏，不要求原消息 ID 仍然存在。

此功能仅通过 Koishi Console authority 4 管理接口提供，未向 MCP 增加原文读取工具。不会调用模型、工作流工具、绘图或 SMTP；不会创建执行记录、修改任务或推进进度。页面切换或关闭预览时清空正文视图。临时窗口不保存到任务；原有“试判断 / 试运行工具”继续使用任务已保存的设置，后者可能产生绘图等费用。

## 验证边界

本地自动验收覆盖时间与数量组合、多模态纯图片、窗口外超大记录、范围内有损摘录、空窗口、时区偏移、缺失时间、摘要替换提示、成功事件选择、旧边界恢复以及只读无副作用。生产环境仍需在升级后通过管理页预览真实会话，核对时间与内容；本地验收不代表生产定时任务已恢复。
